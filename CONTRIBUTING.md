# Как помочь проекту

Спасибо, что хотите помочь. Ниже — правила, которые держат курс цельным.
Подробная версия с примерами — на сайте, на странице
[«Как помочь проекту»](https://mojo-lang.ru/reference/contributing/).

## Правки текста

Самый простой путь: внизу каждой страницы сайта есть ссылка
«Редактировать страницу» — она ведёт прямо в редактор GitHub.

## Правила для примеров кода

1. Ни одно утверждение о языке не берётся по памяти: всё, что можно
   запустить, запускается на настоящем компиляторе.
2. Любой пример, который можно запустить, живёт в `examples/` отдельным
   файлом `.mojo`. Рядом кладётся файл `.out` с ожидаемым выводом.
   Тесты называются `test_*.mojo`, замеры — `bench_*.mojo`, аргументы
   программы кладутся в `.args`, а пример ошибки начинается строкой
   `# ожидается: <текст сообщения>`.
3. Вывод в `<Result>` не набирается руками — только скопированный
   из терминала.
4. Код пишется под **Mojo 1.x**: `def`, `var`, `comptime`, конвенции
   `mut` / `var` / `ref` / `out`, декоратор `@fieldwise_init`.
   Никаких `fn`, `let`, `alias`, `inout`, `borrowed`, `owned`, `@value`.
   Предупреждение `deprecated` проверка считает ошибкой.
5. Перед отправкой прогоните `npm run examples:check`.

## Правила для текста

- Термины берутся из [словаря](src/content/docs/reference/glossary.mdx).
  Хотите изменить перевод термина — сначала обсуждение, потом правка
  сразу на всех страницах.
- При первом употреблении термина: русский вариант, оригинал в скобках курсивом:
  владение (_ownership_).
- Обращение к читателю — на «вы» со строчной буквы.
- Никакого «просто», «легко», «очевидно»: если бы это было очевидно,
  читатель бы сюда не пришёл.
- Каждая глава заканчивается блоком «Проверь себя».
- Рядом с цифрами замеров — процессор, число ядер и методика.

## Новые главы

Хотите добавить главу — сначала откройте issue с обоснованием: почему
она нужна и куда встраивается.

## Лицензии

Отправляя правку, вы соглашаетесь, что текст публикуется под
CC BY-NC-SA 4.0, а код — под Apache 2.0.

## Рабочий процесс

```bash
git checkout -b правка/короткое-описание
# правки
npm run build          # сборка проверяет и ссылки тоже
npm run format         # причёсывает исходники сайта (главы не трогает)
git commit -m "текст: поправил главу про WSL"
git push -u origin правка/короткое-описание
```

Дальше — pull request. CI соберёт сайт и проверит внутренние ссылки,
а при изменении глав или примеров прогонит весь код курса на настоящем
компиляторе Mojo.

Префиксы коммитов, которые мы используем: `текст:`, `код:`, `дизайн:`,
`инфра:`, `правка:`. Строгих требований нет, главное — понятно.

## Локальная проверка примеров

Проверка запускает настоящий компилятор, поэтому нужен Linux, macOS или WSL
с установленным Mojo:

```bash
MOJO_CMD=/путь/к/проекту/.venv/bin/mojo npm run examples:check
```

Программы для видеокарты проверка дополнительно собирает под NVIDIA
и AMD, поэтому видеокарта для неё не нужна.
