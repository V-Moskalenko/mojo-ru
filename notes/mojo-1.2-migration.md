# Переход курса на Mojo 1.2.0

Рабочая заметка: что проверено на компиляторе 1.2.0 (2016d0cd) при миграции
курса с 1.1.0, ноябрь 2026. Всё ниже воспроизведено вручную, не взято
из списка изменений на веру.

Источник: <https://mojolang.org/releases/v1.2.0/>. Исходник заметок
к выпуску лежит в ветке `main` (`Mojo/docs/site/releases/v1.2.0.md`),
по тегу `mojo/v1.2.0` его нет.

## Что поймала проверка курса

CI упал 26.10.2026 на еженедельном прогоне: версия Mojo в CI не закреплена
намеренно, и прогон подтянул 1.2.0.

- `e48_tstring_to_string`: тип t-строки в сообщении теперь
  `TString[origin_of(n), origin_of(__call_result_tmp__)]`.
- `basics/stdlib.mdx`: `log(10.0)` для `Float64` совпадает с Python.
- `interop/testing.mdx`: список из литералов `[0.1, 0.2]` оптимизатор
  сворачивает при сборке, FMA-эффект пропал. На данных из `argv` он есть.

## Чего проверка не поймала

- `async`/`await` дают warning «experimental and unstable» без слова
  «deprecated» — детектор в `scripts/check-examples.mjs` расширен.
- t-строки хранят ссылки: `n = 1; t = t"{n}"; n = 2; print(t)` → `n = 2`
  (в 1.1 было `n = 1`). Ни один пример этого не проверял.
- GPU: `test_fractal` на RTX 4070 Ti SUPER — 0 расхождений на 1.1,
  337 из 307 200 на 1.2, 0 с `--fp-mode contract=off`. PTX почти тот же,
  разница при переводе PTX в SASS. У CI видеокарты нет.
- `<Result>…</Result>` с содержимым внутри тега проверкой **не сверяется** —
  только форма `<Result output={"..."} />` сразу после блока.

## Сопоставление с образцом: проверенные факты

- Литералы, `|`, имя, `if`-охрана, `_`, `as`, `== значение`, кортежи
  (`match a, b:` без скобок), `Point(x=0, y=y)`, `.Some(x)` / `.None`,
  списки `[first, *middle, last]`.
- Имя в `case` живёт только в ветке (в Python перезаписывает внешнее).
- Полнота: предупреждения для `Bool`, `Optional`, кортежей из `Bool`
  («missing case for 'False, False'»); для списков полноту не доказывает —
  нужен `case _:`, иначе `return expected at end of function`.
- Образцы структур только по именам полей: позиционные — ошибка
  `struct patterns do not support positional or unpacked arguments`.
- `Variant` образцами не разбирается: `cannot match value of type
  'Variant[Int, String]' against pattern type 'Int'`.
- Образец «список инициализации» `{x = 5, y = ...}` в 1.2 работает плохо
  (ошибки и с привязкой, и с `_`) — в курс не взят.
- `var [a, b] = xs` при несовпадении длины бросает
  `list pattern does not match value length`, требует `raises`.
- `comptime match`: связанные имена — параметры; `var`/`ref` запрещены;
  по переменной — `cannot use a dynamic value in 'match' subject`.

## Прочее

- `where cond else "текст"`; несколько клауз `where` подряд, у каждой своё
  сообщение. Кортежная форма `where (cond, "текст")` работала уже в 1.1.
- `not Movable [else "..."]`: запрещает `var q = p^` и `List[T]`; возврат
  из функции, передача по ссылке и `f(p^)` в `var`-аргумент работают.
  Текст после `else` в сообщениях не показывается.
- Структура без трейтов перемещаема и годится для `List` (1.1 и 1.2).
- `.mojoc` 1.1 ↔ 1.2 не совместимы в обе стороны (`older than` / `newer than`).
- Рантайм для переносимых сборок: те же три библиотеки, GLIBC_2.35,
  GLIBCXX_3.4.30; лицензия в метаданных PyPI 1.2.0 всё ещё MAX.
- `ascii_rjust` считает байты: `"кот".ascii_rjust(6)` → `"кот"`.
- Пример из официальных заметок `hash(text.ptr(), …)` для `String`
  не компилируется (`ptr` нет); перегрузка с `unsafe_ptr()` даёт
  предупреждение «Use `hash_bytes()` instead».
