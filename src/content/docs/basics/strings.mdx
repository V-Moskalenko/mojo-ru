Для англоязычного читателя эта глава была бы скучной: в ASCII символ равен
байту, и говорить не о чем. Для нас всё интереснее — каждая русская буква
занимает два байта, и Mojo не даёт об этом забыть.

Хорошая новость: язык не прячет сложность, а заставляет один раз принять
решение — и дальше всё работает предсказуемо.

## У строки нет одной длины

Привычное `len(s)` для строки в Mojo просто запрещено:

<CompilerError msg="error: `len(String/StringSlice)` is not supported because Mojo strings are UTF-8 encoded, so a single length is ambiguous">
  <Fragment slot="meaning">
    Компилятор отказывается угадывать, что вы имели в виду под «длиной».
    Для строки «Привет» есть три честных ответа: 12 байт, 6 кодовых точек
    и 6 видимых знаков.
  </Fragment>
  <Fragment slot="fix">
    Скажите явно, что считаете:

    - `s.byte_length()` — сколько байт занимает строка в памяти;
    - `len(s.codepoints())` — сколько символов Unicode;
    - `len(s.graphemes())` — сколько знаков видит человек.
  </Fragment>
</CompilerError>

Для латиницы все три числа совпадают, поэтому в англоязычных учебниках
разницы не видно. Для кириллицы — уже нет:

| Строка | Байт | Кодовых точек | Видимых знаков |
| --- | --- | --- | --- |
| `"hello"` | 5 | 5 | 5 |
| `"Привет"` | 12 | 6 | 6 |
| `"👨‍👩‍👧"` | 18 | 5 | 1 |

Последняя строка — эмодзи «семья». Один видимый знак, который на самом деле
склеен из трёх человечков и двух невидимых соединителей. Отсюда и разница
между «кодовой точкой» и «видимым знаком».

<Aside type="note" title="Три уровня, если совсем коротко">
  **Байт** — единица памяти. Кириллица занимает два байта на букву,
  эмодзи — четыре и больше.

  **Кодовая точка** (*code point*) — то, что Unicode считает одним символом.

  **Графема** (*grapheme*) — то, что человек считает одним знаком:
  буква с диакритикой, эмодзи из нескольких частей, флаг страны.
</Aside>

## Срезы: обязательно указать единицу

Привычный питоновский срез не работает:

<PyMojo>
  <Fragment slot="python">
```python
s = "Привет"
print(s[0:3])      # При
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
var s = String("Привет")
print(s[codepoint=0:3])   # При
print(s[byte=0:4])        # Пр
```
  </Fragment>
  <Fragment slot="note">
    Четыре байта — это всего две русские буквы. Именно так и появляются
    «кракозябры»: обрезали строку на середине символа.
  </Fragment>
</PyMojo>

<CompilerError msg="error: String does not support direct positional slicing like `s[a:b]` because Mojo strings are UTF-8 encoded, and the same range can mean different things. Use `s[byte=a:b]` to slice by raw UTF-8 byte positions, or `s[codepoint=a:b]` to slice by Unicode code points.">
  <Fragment slot="meaning">
    Срез без указания единицы измерения.
  </Fragment>
  <Fragment slot="fix">
    Решение прямо в сообщении. Практическое правило: работаете с текстом
    для человека — `codepoint`; работаете с данными, протоколом или
    результатом `find()` — `byte`.
  </Fragment>
</CompilerError>

Резать по графемам (`s[grapheme=…]`) в 1.0 нельзя — только перебирать
их через `s.graphemes()`.

## Поиск возвращает байты

Тонкость, о которой стоит знать до того, как она испортит вам вечер:

```mojo
def main():
    var text = String("мама мыла раму")
    print(text.find("мыла"))          # 9
    print(len("мама ".codepoints()))  # 5
```

<Result>
9
5
</Result>

Подстрока начинается с шестого символа, но `find` вернул 9 — потому что
считает **байты**. Это не ошибка: так результат согласован со срезом
по байтам, и их можно использовать вместе:

```mojo
var position = text.find("мыла")
print(text[byte=position : position + 8])   # мыла
```

Восемь байт — это четыре русские буквы. Если попытаться подставить тот же
индекс в срез по кодовым точкам, получится сдвиг.

## Перебор строки

```mojo
def main():
    for symbol in String("ёжик").codepoints():
        print(symbol, end="|")
    print()
```

<Result>
ё|ж|и|к|
</Result>

Аналогично работают `.graphemes()` — по видимым знакам и `.bytes()` — по
сырым байтам. Для эмодзи и букв с диакритикой правильный выбор почти всегда
`.graphemes()`: только он не разрежет знак на части.

## Что работает как в Python

Приятная часть: почти вся привычная работа со строками переносится
без изменений.

```mojo
def main():
    var s = String("мама мыла раму")

    print(s.replace("раму", "окно"))
    print(s.startswith("мама"), s.endswith("раму"))
    print(s.count("ма"), s.rfind("ма"))
    print("мыла" in s)
    print(String("  тест  ").strip())
    print(String("ПРИВЕТ").lower(), String("привет").upper())
```

<Result>
мама мыла окно
True True
2 4
True
тест
привет ПРИВЕТ
</Result>

Регистр корректно работает и для кириллицы, включая букву «ё»:
`"ёжик".upper()` даёт `ЁЖИК`.

Разбиение и склейка тоже на месте:

```mojo
def main():
    var parts = String("а,б,в").split(",")
    print(len(parts))
    print(String(", ").join(parts))
```

<Result>
3
а, б, в
</Result>

Многострочные строки в тройных кавычках и экранирование `\n`, `\t`
работают как в Python.

## Ловушка: «ё» бывает разная

```mojo
def main():
    var one = String("ё")          # одна кодовая точка
    var two = String("\u0435\u0308")  # «е» плюс комбинирующие точки

    print(one.byte_length(), two.byte_length())
    print(len(one.graphemes()), len(two.graphemes()))
    print(one == two)
```

<Result>
2 4
1 1
False
</Result>

Выглядят одинаково, занимают разное место и **не равны** при сравнении.
Такое приходит из внешних источников: копипаст с сайтов, выгрузки из систем,
данные с macOS, где исторически предпочитают второй вариант.

Готовой функции нормализации в стандартной библиотеке Mojo 1.0 найти
не удалось. Практический совет:
если данные приходят извне и вы их сравниваете — приводите к одной форме
на входе, например средствами Python через
[interop](/interop/python-from-mojo/), где есть `unicodedata.normalize`.

<Aside type="caution" title="Почему это не «придирка языка»">
  В Python эта же проблема существует — просто она молчит до продакшена.
  Там `len("Привет")` вернёт 6, а `len("Привет".encode())` — 12, и легко
  перепутать, когда пишете в файл фиксированной ширины или считаете
  позицию курсора. Mojo заставляет выбрать сразу и потому не даёт
  ошибиться молча.
</Aside>

## Собираем строку из кусков

```mojo
def main():
    var result = String("")
    for i in range(3):
        result += String(i)
    print(result)
```

<Result>
012
</Result>

Работает, но помните: каждое `+=` может приводить к перевыделению памяти.
Для длинных циклов лучше собрать части в `List[String]` и склеить одним
`join` — это одна аллокация вместо сотни.

    буква занимает два байта: «мама » — это 9 байт. Такой результат
    согласован со срезом `s[byte=...]`, их удобно использовать вместе.
  </QuizItem>

  </QuizItem>
  <QuizItem q="Что выбрать для среза: byte или codepoint?">
    Для текста, который читает человек, — `codepoint`: он не разрежет
    букву пополам. Для работы с данными и вместе с результатом `find()` —
    `byte`. Смешивать их в одном вычислении нельзя.
  </QuizItem>
</Quiz>
