Если [окружение уже настроено](/install/windows-wsl/), напишем первую
осмысленную программу и разберём её построчно. Она короткая, но в ней уже
видны три главных отличия Mojo от Python.

## Программа целиком

```mojo title="temperature.mojo"
def average(values: List[Float64]) -> Float64:
    var total = 0.0
    for value in values:
        total += value
    return total / len(values)


def main():
    var measurements = List[Float64](21.5, 23.0, 19.8, 24.2)
    var mean = average(measurements)
    print("Средняя температура:", mean)
```

Запустим:

```bash
uv run mojo temperature.mojo
```

<Result>
Средняя температура: 22.125
</Result>

## Разбор по строкам

### `def main()` — обязательная точка входа

```mojo
def main():
    print("Привет!")
```

В Python код можно писать прямо на верхнем уровне файла, и он выполнится
сверху вниз. В Mojo так нельзя: **каждая программа обязана содержать функцию
`main()`** — именно с неё начинается выполнение.

<PyMojo>
  <Fragment slot="python">
```python
# Работает: код на верхнем уровне
print("Привет!")
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
# Обязательно внутри main()
def main():
    print("Привет!")
```
  </Fragment>
  <Fragment slot="note">
    В коротких примерах этого курса `def main()` иногда опускается ради
    краткости — как и в официальном мануале. Но чтобы запустить такой
    фрагмент у себя, оберните его в `main()`.
  </Fragment>
</PyMojo>

<Aside type="caution" title="Если вы видели `fn main()` — это устаревший код">
  До 2026 года в Mojo было два ключевых слова для функций: `def` и `fn`.
  К версии 1.0 язык оставил только `def`, а `fn` объявлен устаревшим.
  Большинство статей и видео в интернете написаны до этого изменения —
  их код на Mojo 1.0 не соберётся. Полный список таких ловушек мы собрали
  на странице [Устаревшие конструкции](/python-to-mojo/outdated/).
</Aside>

### Типы аргументов обязательны

```mojo
def average(values: List[Float64]) -> Float64:
```

В Python аннотации типов — подсказка для человека и линтера; интерпретатору
на них всё равно. В Mojo тип — это указание компилятору, как разместить
значение в памяти и какие машинные инструкции сгенерировать. Без типа
компилятор не может собрать эффективный код, поэтому типы аргументов
и возвращаемого значения обязательны.

Именно отсюда берётся скорость: `Float64` — это не объект с заголовком,
счётчиком ссылок и таблицей методов, как `float` в CPython, а восемь байт
в регистре процессора.

<PyMojo>
  <Fragment slot="python">
```python
def average(values):
    return sum(values) / len(values)
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
def average(values: List[Float64]) -> Float64:
    var total = 0.0
    for value in values:
        total += value
    return total / len(values)
```
  </Fragment>
  <Fragment slot="note">
    Аннотация `-> Float64` — это не документация, а контракт: компилятор
    проверит его на этапе сборки, а не в момент падения программы у пользователя.
  </Fragment>
</PyMojo>

### `var` и объявление переменных

```mojo
var total = 0.0
```

Переменную можно объявить двумя способами:

```mojo
var count: Int = 0     # явное объявление с типом
var count = 0          # явное объявление, тип выведен из значения
count = 0              # неявное объявление
```

Разница между `var` и объявлением без него — в области видимости.
Переменные с `var` живут в пределах своего блока (как в C++ или Rust),
переменные без `var` — в пределах всей функции (как в Python).

<Aside type="note" title="`let` в Mojo больше нет">
  В ранних версиях языка была пара `let` / `var` — для неизменяемых
  и изменяемых переменных. В Mojo 1.0 `let` удалён: все переменные
  изменяемы. Неизменяемость теперь выражается не типом переменной,
  а [конвенцией передачи аргументов](/ownership/conventions/) —
  это принципиально другая, более точная модель.
</Aside>

## Компиляция в исполняемый файл

`mojo temperature.mojo` компилирует и сразу запускает программу — удобно
при разработке. Но Mojo — компилируемый язык, и результат можно получить
в виде обычного исполняемого файла:

```bash
uv run mojo build temperature.mojo
./temperature
```

<Result>
Средняя температура: 22.125
</Result>

Получившийся бинарник не требует ни интерпретатора, ни виртуального
окружения — его можно просто скопировать на другую машину с той же
архитектурой и запустить. Для Python-разработчика это, пожалуй, самое
непривычное ощущение от языка.

## Когда что-то пошло не так

<CompilerError msg="error: expected type in function signature">
  <Fragment slot="meaning">
    У аргумента функции не указан тип. Компилятор дошёл до имени аргумента,
    ожидал двоеточие и тип, но не нашёл их.
  </Fragment>
  <Fragment slot="fix">
    Допишите тип: `def average(values: List[Float64]) -> Float64:`.
    Привычка из Python писать `def average(values)` здесь не работает.
  </Fragment>
</CompilerError>

<CompilerError msg="error: 'fn' is deprecated, use 'def' instead">
  <Fragment slot="meaning">
    Вы используете ключевое слово `fn`, оставшееся от старых версий языка.
  </Fragment>
  <Fragment slot="fix">
    Замените `fn` на `def`. Семантика при этом не меняется: в Mojo 1.0
    `def` ведёт себя ровно так, как раньше вёл себя `fn` — в частности,
    функция не считается способной бросать исключения, пока вы явно
    не напишете `raises`.
  </Fragment>
</CompilerError>

<Quiz>
  <QuizItem q="Почему в Mojo нельзя писать код на верхнем уровне файла, как в Python?">
    Потому что Mojo — компилируемый язык, а не интерпретируемый: у программы
    должна быть определённая точка входа, с которой начинается выполнение
    собранного бинарника. Эту роль играет функция `main()`.
  </QuizItem>
  <QuizItem q="Чем аннотация типа в Mojo отличается от аннотации типа в Python?">
    В Python аннотация ни на что не влияет во время выполнения — это подсказка
    для человека и инструментов. В Mojo тип определяет представление значения
    в памяти и генерируемый машинный код, поэтому он обязателен и проверяется
    компилятором.
  </QuizItem>
  <QuizItem q="В чём разница между `var x = 0` и `x = 0` внутри функции?">
    В области видимости. `var x` живёт до конца блока, в котором объявлен
    (например, внутри `if`), а `x = 0` без `var` — до конца всей функции,
    как в Python.
  </QuizItem>
</Quiz>
