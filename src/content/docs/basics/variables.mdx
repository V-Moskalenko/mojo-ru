В Python переменная — это имя, привязанное к объекту, и её можно в любой
момент перепривязать к чему угодно. В Mojo переменная — это участок памяти
известного размера с известным типом. Отсюда все отличия ниже.

## Объявление

Переменная объявляется словом `var` при первом присваивании:

```mojo
var count: Int = 0     # с явным типом
var total = 0.0        # тип выведен из значения — здесь Float64
var name = "Аня"       # String
```

Дальше `var` не нужен — это уже не объявление, а изменение значения:

```mojo
count = 5
count += 1
```

<Aside type="caution" title="Без `var` пока можно, но не нужно">
  Присваивание без `var` при первом упоминании ещё работает, но компилятор
  выдаёт предупреждение:

  ```text
  warning: implicit declaration of 'count' is deprecated;
  add 'var' before the assignment target
  ```

  Сегодня это предупреждение, в следующих версиях станет ошибкой. Пишите
  `var` сразу — переучиваться потом дороже.
</Aside>

## Тип фиксируется навсегда

Тип переменной определяется в момент объявления и больше не меняется:

<PyMojo>
  <Fragment slot="python">
```python
x = 1
x = "теперь строка"   # нормально
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
var x = 1
x = "теперь строка"   # ошибка компиляции
```
  </Fragment>
  <Fragment slot="note">
    В Python имя просто перевешивается на другой объект. В Mojo под `x`
    отведено восемь байт под целое число — строка туда не поместится
    ни физически, ни по смыслу.
  </Fragment>
</PyMojo>

<CompilerError msg="error: cannot implicitly convert 'StringLiteral[...]' value to 'Int'">
  <Fragment slot="meaning">
    Вы присваиваете переменной значение другого типа.
  </Fragment>
  <Fragment slot="fix">
    Либо заведите новую переменную с другим именем, либо преобразуйте
    значение явно: `var text = String(x)`.
  </Fragment>
</CompilerError>

## Объявить сейчас, присвоить позже

Так можно — но пользоваться значением до присваивания компилятор не даст:

```mojo
var limit: Int      # объявлена, но пуста
limit = 100         # теперь в ней есть значение
```

<CompilerError msg="error: use of uninitialized value 'x'">
  <Fragment slot="meaning">
    Переменная объявлена, но значение в неё ещё не положили — а вы уже
    пытаетесь его прочитать.
  </Fragment>
  <Fragment slot="fix">
    Присвойте значение до первого использования. Компилятор отслеживает
    все ветви кода: если хотя бы по одной из них переменная остаётся
    пустой, будет ошибка.
  </Fragment>
</CompilerError>

Это важнее, чем кажется. В Python неинициализированная переменная —
это `NameError` во время выполнения, у пользователя. В Mojo такой код
просто не соберётся.

## Область видимости — по блокам

Главное отличие от Python. Переменная живёт до конца блока, в котором
объявлена, а не до конца функции:

<PyMojo>
  <Fragment slot="python">
```python
if True:
    message = "привет"
print(message)   # работает
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
if True:
    var message = "привет"
print(message)   # ошибка: имя неизвестно
```
  </Fragment>
  <Fragment slot="note">
    Блок — это тело `if`, `while`, `for`, `with` и любой другой
    конструкции с отступом. Как в C++, Rust или Java.
  </Fragment>
</PyMojo>

<CompilerError msg="error: use of unknown declaration 'message'">
  <Fragment slot="meaning">
    Имя не существует в этой точке программы: либо опечатка, либо
    переменная объявлена во вложенном блоке и уже «умерла».
  </Fragment>
  <Fragment slot="fix">
    Объявите переменную до блока, если она нужна и после него.
  </Fragment>
</CompilerError>

Внутри вложенного блока имя можно **затенить** (*shadow*) — это будет
отдельная переменная, а внешняя останется нетронутой.

## Все переменные изменяемы

В ранних версиях Mojo была пара `let` и `var` — для неизменяемых
и изменяемых переменных. В 1.0 `let` удалён: любую переменную можно
изменить.

Означает ли это, что от неизменяемости отказались? Нет — её перенесли
туда, где она действительно нужна: в передачу аргументов. Функция
получает значение только для чтения, если явно не сказано иначе.
Подробно — в главе [Конвенции передачи
аргументов](/ownership/conventions/).

## Константы времени компиляции

Если значение известно заранее и меняться не должно, объявите его через
`comptime` — компилятор вычислит его на этапе сборки и подставит в код:

```mojo
comptime MAX_USERS = 100


def main():
    comptime BUFFER = 4096
    print(MAX_USERS, BUFFER)
```

<Result>
100 4096
</Result>

Такие значения можно использовать там, где обычная переменная не подойдёт —
например, задавать размер массива или ширину SIMD-вектора. Об этом целый
раздел [Метапрограммирование](/meta/comptime/).

<Aside type="note" title="Про `alias`">
  В коде и статьях вам встретится ключевое слово `alias` — оно делает
  примерно то же самое и пока работает. Но в новом коде используйте
  `comptime`: именно к нему язык пришёл в 1.0.
</Aside>

## Имена

Правила как в Python: буквы, цифры, подчёркивания, начинать с цифры нельзя.
Кириллица в именах технически возможна, но не используйте её — код читают
и правят разные люди, а раскладку переключать неудобно.

Принятый стиль в Mojo совпадает с питоновским: `snake_case` для переменных
и функций, `CamelCase` для типов, `UPPER_CASE` для констант.

<Quiz>
  <QuizItem q="Почему `var message` внутри `if` не виден после блока?">
    В Mojo область видимости переменной ограничена блоком, где она объявлена.
    Это позволяет компилятору точно знать, когда значение больше не нужно,
    и вовремя освободить память. В Python область видимости — вся функция.
  </QuizItem>
  <QuizItem q="Можно ли объявить переменную без значения?">
    Да: `var limit: Int`. Но прочитать её до первого присваивания нельзя —
    компилятор проверяет все ветви кода и выдаст ошибку
    `use of uninitialized value`.
  </QuizItem>
  <QuizItem q="Куда делось ключевое слово `let` из старых примеров?">
    Удалено в Mojo 1.0. Все переменные изменяемы, а неизменяемость выражается
    конвенцией передачи аргументов: функция по умолчанию получает значение
    только для чтения.
  </QuizItem>
</Quiz>
