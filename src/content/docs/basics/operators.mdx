Операторы в Mojo выглядят и ведут себя как в Python — с одним важным
исключением, о котором мы уже говорили в главе про типы. Зато появляется
возможность, которой в Python нет: операторы можно определить для своих
типов без потери скорости.

## Арифметика

```mojo
def main():
    print(2 + 3 * 4)      # приоритет как в математике
    print((2 + 3) * 4)
    print(2**10)          # степень
    print(7 % 3)          # остаток
    print(7 // 2)         # целочисленное деление
```

<Result>
14
20
1024
1
3
</Result>

<Aside type="caution" title="Помните про деление">
  `7 / 2` на литералах даёт `3.5`, но деление двух переменных типа `Int`
  даёт `Int` — дробная часть отбрасывается. Это самая частая ловушка
  для питониста, разобрана в главе [Система типов](/basics/types/).
</Aside>

Составные присваивания `+=`, `-=`, `*=`, `/=`, `//=`, `%=`, `**=` работают
как обычно. Операторов `++` и `--` нет — как и в Python.

## Сравнения

```mojo
def main():
    var age = 25
    print(age == 25, age != 30, age > 18)
    print(18 <= age < 65)     # цепочка сравнений
```

<Result>
True True True
True
</Result>

Цепочки сравнений — приятное наследие Python: `18 <= age < 65` читается
как в математике и вычисляется один раз, без повторного обращения к `age`.

Строки сравниваются посимвольно, по кодовым точкам:

```mojo
def main():
    print(String("а") < String("б"))
    print(String("абв") == String("абв"))
```

<Result>
True
True
</Result>

<Aside type="note" title="Осторожно с алфавитным порядком">
  Сравнение идёт по номерам символов Unicode, а не по правилам русского
  алфавита. Заглавные буквы «меньше» строчных, а буква «ё» стоит далеко
  от «е» — в Unicode она вынесена отдельно. Для сортировки списка городов
  или фамилий этого недостаточно, нужна нормализация или своя функция сравнения.
</Aside>

## Логические операции

```mojo
def main():
    print(True and False, True or False, not True)
```

<Result>
False True False
</Result>

Как и в Python, `and` и `or` вычисляются лениво: если результат уже ясен
по левому операнду, правый не вычисляется. Это позволяет писать привычное
`if index < len(items) and items[index] > 0`.

## Побитовые операции

```mojo
def main():
    print(5 & 3, 5 | 3, 5 ^ 3)    # и, или, исключающее или
    print(1 << 4, 16 >> 2)        # сдвиги
```

<Result>
1 7 6
16 4
</Result>

В Python побитовые операции — экзотика. В Mojo, где вы работаете
с конкретными размерными типами, флагами и данными, они встречаются
заметно чаще.

## Тернарный оператор и «морж»

Обе конструкции перенесены из Python без изменений:

```mojo
def main():
    var temperature = 25
    print("тепло" if temperature > 20 else "прохладно")

    var count: Int
    if (count := temperature // 10) > 1:
        print("десятков:", count)
```

<Result>
тепло
десятков: 2
</Result>

Оператор `:=` присваивает и сразу возвращает значение — удобно, когда
результат нужен и в условии, и в теле.

<Aside type="caution" title="Переменную для «моржа» объявляйте заранее">
  Если написать `if (count := ...)` без предварительного `var count: Int`,
  код соберётся, но компилятор предупредит:

  ```text
  warning: implicit declaration of 'count' is deprecated;
  declare it with 'var' in the function body
  ```

  Причина та же, что и с обычными переменными: неявное объявление
  в Mojo 1.0 устарело.
</Aside>

## Свои операторы для своих типов

Вот здесь Mojo интереснее Python. Чтобы структура умела складываться,
достаточно определить метод `__add__`:

```mojo
@fieldwise_init
struct Money(ImplicitlyCopyable):
    var amount: Int

    def __add__(self, other: Money) -> Money:
        return Money(self.amount + other.amount)


def main():
    var total = Money(100) + Money(250)
    print(total.amount)
```

<Result>
350
</Result>

Никакой динамической диспетчеризации при этом не происходит: компилятор
подставляет вызов напрямую, и `Money(100) + Money(250)` стоит ровно столько
же, сколько сложение двух чисел.

### Какие методы за что отвечают

| Оператор | Метод |
| --- | --- |
| `a + b` | `__add__` |
| `a - b` | `__sub__` |
| `a * b` | `__mul__` |
| `a / b` | `__truediv__` |
| `a // b` | `__floordiv__` |
| `a % b` | `__mod__` |
| `a ** b` | `__pow__` |
| `a == b` | `__eq__` |
| `a != b` | `__ne__` |
| `a < b` | `__lt__` |
| `a <= b` | `__le__` |
| `a > b` | `__gt__` |
| `a >= b` | `__ge__` |
| `a[i]` | `__getitem__` |
| `len(a)` | `__len__` |
| `x in a` | `__contains__` |

Имена совпадают с питоновскими — если вы когда-нибудь писали классы
с `__eq__`, здесь всё знакомо.

<Aside type="caution" title="Для `len()` одного метода мало">
  С операторами достаточно определить метод. А вот встроенные функции
  требуют, чтобы тип ещё и **соответствовал трейту**. Определив только
  `__len__`, вы получите:

  ```text
  error: no matching function in call to 'len'
  note: argument type 'Box' does not conform to trait 'Sized'
  ```

  Лечится добавлением трейта в объявление структуры:
  `struct Box(ImplicitlyCopyable, Sized):`. Что такое трейты и зачем
  они нужны — в разделе [Метапрограммирование](/meta/traits/).
</Aside>

<Aside type="tip" title="Операторы работают и над векторами">
  Если применить оператор к значению типа `SIMD`, он выполнится сразу
  над всеми элементами: `SIMD[DType.float32, 4](1, 2, 3, 4) * 2` даёт
  `[2.0, 4.0, 6.0, 8.0]` за одну инструкцию процессора. Об этом —
  в главе [SIMD с нуля](/performance/simd/).
</Aside>

<Quiz>
  <QuizItem q="Что нужно добавить в структуру, чтобы работал оператор `==`?">
    Метод `__eq__(self, other: ...) -> Bool`. Имена методов совпадают
    с питоновскими, так что если вы писали классы с `__eq__` в Python —
    здесь ровно то же самое.
  </QuizItem>
  <QuizItem q="Почему сравнение строк не годится для сортировки по алфавиту?">
    Оно идёт по номерам символов в Unicode: заглавные буквы оказываются
    «меньше» строчных, а «ё» стоит далеко от «е». Для человеческого порядка
    нужна нормализация или своя функция сравнения.
  </QuizItem>
  <QuizItem q="Стоит ли перегрузка оператора дороже обычного вызова функции?">
    Нет. Вызов подставляется компилятором напрямую, динамического поиска
    метода во время выполнения не происходит — в отличие от Python.
  </QuizItem>
</Quiz>
