Самая «питоновская» глава раздела: почти всё переносится дословно.
Поэтому сосредоточимся на том, что всё-таки отличается, — включая
`match`, который в Mojo появился только в версии 1.2.

## Ветвление

```mojo
def main():
    var temperature = 25

    if temperature > 30:
        print("жарко")
    elif temperature > 20:
        print("тепло")
    else:
        print("прохладно")

    print("одеваться:", "легко" if temperature > 20 else "тепло")
```

<Result>
тепло
одеваться: легко
</Result>

`if` / `elif` / `else` и тернарный оператор — без единого отличия от Python.

## Сопоставление с образцом: `match`

С версии 1.2 в Mojo есть `match` / `case` — **сопоставление с образцом**
(_pattern matching_), знакомое по Python 3.10. Значение сравнивается
с образцами сверху вниз, и выполняется ветка первого подошедшего:

<Code code={match} lang="mojo" title="match.mojo" />

<Result output={"200 — всё хорошо\n302 — страница переехала\n404 — нет такой страницы (404)\n503 — сломался сервер, код 503\n418 — что-то другое\nсогласие отказ непонятно\n1 2 Fizz 4 Buzz Fizz 7 8 Fizz Buzz 11 Fizz 13 14 FizzBuzz"} />

Что бывает в `case`:

| Образец | Пример | Когда подходит |
| --- | --- | --- |
| литерал | `case 200:`, `case "да":` | значение равно литералу |
| «или» | `case 301 \| 302:` | подходит любой из вариантов |
| имя | `case c:` | всегда; значение получает имя `c` |
| охранное условие | `case c if c >= 500:` | образец подошёл **и** условие истинно |
| подстановочный | `case _:` | всегда, ничего не связывая |
| `as` | `case 404 as missing:` | образец подошёл; всё значение — в `missing` |
| кортеж | `case True, False:` | каждый элемент — своему образцу |

Как и в Python, ветки не «проваливаются» друг в друга: `break` в конце
не нужен, и выполняется не больше одной. Если не подошла ни одна, `match`
просто ничего не делает. Последняя функция показывает приём, ради
которого `match` любят: сопоставлять можно сразу несколько значений.
Скобки вокруг кортежа необязательны.

Образцы бывают и сложнее: они заглядывают внутрь структур, `Optional`
и списков. До них дойдём в главах [«Структуры»](/basics/structs/)
и [«Коллекции и итераторы»](/basics/collections/), когда эти типы
будут знакомы.

### Имя в образце — всегда новое имя

Главная ловушка — та же, что в Python, но последствия у неё другие.
Голое имя в `case` не сравнивает значение с переменной, а **создаёт
новую**:

В Python:

```python
limit = 100
reading = 42
match reading:
    case 100:
        print("на пределе")
    case limit:
        print("limit =", limit)
print("снаружи:", limit)
```

```text
limit = 42
снаружи: 42
```

`case limit:` молча **перезаписал** внешнюю переменную: после `match`
она равна 42. То же в Mojo:

```mojo
def main():
    var limit = 100
    var reading = 42
    match reading:
        case == limit:
            print("на пределе")
        case limit:
            print("limit =", limit)
    print("снаружи:", limit)
```

<Result output={"limit = 42\nснаружи: 100"} />

Новое имя живёт только внутри своей ветки, и снаружи `limit`
по-прежнему 100. А сравнить со значением переменной можно явно — через
`case == limit:`. В Python так нельзя: там для этого нужно имя с точкой,
вроде `case Limits.MAX:`.

### Компилятор следит за полнотой

Если у типа фиксированный набор значений, как у `Bool`, компилятор
предупредит, что вы забыли вариант. Предупредит и о ветке, до которой
дело никогда не дойдёт:

```text
warning: 'match' is not exhaustive; missing case for 'False'
warning: case is unreachable; previous cases cover every value of the match subject
```

Python во втором случае вообще отказывается запускать программу:
`SyntaxError: name capture 'limit' makes remaining patterns unreachable`.
Mojo только предупреждает, но относитесь к этим предупреждениям как
к ошибкам: почти всегда они означают перепутанный порядок веток.
У `Int` и `String` значений бесконечно много, поэтому полноты от них
никто не требует — для них и нужен `case _:`.

## Циклы

`while` и `for ... in` работают привычно, `range` принимает те же три
формы, включая отрицательный шаг:

```mojo
def main():
    for i in range(10, 0, -3):
        print(i, end=" ")
    print()
```

<Result>
10 7 4 1
</Result>

Есть и редкая питоновская конструкция `for ... else` — блок `else`
выполняется, если цикл завершился без `break`. Работает она и с `while`.

## Перебор коллекций

`enumerate` и `zip` на месте:

```mojo
def main():
    var cities: List[String] = ["Москва", "Казань"]
    var population: List[Int] = [13, 1]

    for index, city in enumerate(cities):
        print(index, city)

    for pair in zip(cities, population):
        print(pair[0], "—", pair[1], "млн")
```

<Result>
0 Москва
1 Казань
Москва — 13 млн
Казань — 1 млн
</Result>

Обратите внимание на разницу: `enumerate` даёт распаковку в две переменные,
а элементы `zip` приходят кортежем, к которому обращаются по индексу.

Есть и `reversed` для обхода в обратном порядке.

## Изменение элементов прямо в цикле

А вот это отличается от Python по существу. В Python переменная цикла —
копия ссылки на элемент, и присваивание ей ничего не меняет в списке.
В Mojo можно получить **ссылку** на элемент через `ref`:

<PyMojo>
  <Fragment slot="python">
```python
for i in range(len(numbers)):
    numbers[i] *= 10
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
for ref value in numbers:
    value *= 10
```
  </Fragment>
  <Fragment slot="note">
    Вариант с индексами тоже работает, но `ref` читается лучше и не даёт
    ошибиться с границами. Без `ref` переменная цикла доступна только
    для чтения, и `value *= 10` не скомпилируется: `expression must be
    mutable for in-place operator destination`.
  </Fragment>
</PyMojo>

## Перебор словаря

Здесь Mojo честнее Python. Обращение по ключу может не найти значение,
поэтому оно способно бросить исключение:

<CompilerError msg="error: cannot call function that may raise in a context that cannot raise">
  <Fragment slot="meaning">
    Вы написали `codes[city]` внутри обычной функции. Обращение к словарю
    по ключу — операция, которая может завершиться ошибкой, если ключа нет.
  </Fragment>
  <Fragment slot="fix">
    Либо пометьте функцию как `raises`, либо перебирайте пары через
    `.items()` — тогда ключ и значение приходят сразу, и обращаться
    по ключу не нужно.
  </Fragment>
</CompilerError>

```mojo
def main():
    var codes = Dict[String, Int]()
    codes["Москва"] = 495
    codes["Казань"] = 843

    for item in codes.items():
        print(item.key, item.value)
```

<Result>
Москва 495
Казань 843
</Result>

Отдельно доступны `.keys()` и `.values()`, а `for city in codes` перебирает
ключи — как в Python.

## Полезные встроенные функции

Проверено на Mojo: `len`, `abs`, `min`, `max`, `round`, `pow`, `sort`,
`enumerate`, `zip`, `reversed`, `range` — на месте. Есть и `any` с `all`,
но принимают они коллекцию, а не отдельное значение:

```mojo
def main():
    var flags: List[Bool] = [True, False]
    print(any(flags), all(flags))
```

<Result>
True False
</Result>

А вот привычного `sum` в языке **нет**. Сумму списка считают циклом:

```mojo
def main():
    var values: List[Int] = [3, 1, 2]
    var total = 0
    for value in values:
        total += value
    print(total)
```

<Result>
6
</Result>

<Aside type="tip" title="Это не потеря">
  Цикл здесь не медленнее и не хуже: компилятор превратит его в те же
  инструкции, что и вызов `sum`. А когда дойдёт до больших массивов,
  вместо цикла вы будете писать `reduce_add()` над SIMD-вектором —
  и это уже быстрее любого питоновского `sum`.
</Aside>

<Quiz>
  <QuizItem q="Как изменить элементы списка прямо в цикле?">
    Через `for ref value in numbers:` — тогда переменная цикла становится
    ссылкой на элемент, и `value *= 10` меняет сам список. Без `ref`
    переменная цикла только для чтения, и такое присваивание
    не скомпилируется.
  </QuizItem>
  <QuizItem q="Почему `for city in codes: print(codes[city])` не компилируется?">
    Обращение к словарю по ключу может бросить исключение, если ключа нет.
    Значит, вызывающая функция должна быть помечена `raises` — либо нужно
    перебирать `.items()`, где ключ и значение приходят вместе.
  </QuizItem>
  <QuizItem q="Переменная `limit = 100`, а в `match` стоит ветка `case limit:`. Что она проверяет?">
    Ничего: голое имя в образце подходит к любому значению и создаёт
    новое имя `limit`, видимое только внутри ветки. Чтобы сравнить
    со значением переменной, нужно `case == limit:`. В отличие от Python,
    внешняя переменная при этом не перезаписывается.
  </QuizItem>
  <QuizItem q="Как в одном `match` разобрать сразу два условия — делимость на 3 и на 5?">
    Сопоставить кортеж: `match n % 3 == 0, n % 5 == 0:` и ветки
    `case True, True:`, `case True, False:` и так далее. Скобки вокруг
    кортежа необязательны, а если забыть один из четырёх вариантов,
    компилятор предупредит, что `match` неполный.
  </QuizItem>
</Quiz>
