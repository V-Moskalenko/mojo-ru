В Python у аргумента нет никакого «режима»: он просто передаётся,
а что с ним можно делать — выясняется опытным путём.

В Mojo режим написан в сигнатуре. Их пять, но в повседневном коде вы
будете пользоваться первыми тремя.

| Слово | Что функция получает | Когда нужно |
| --- | --- | --- |
| ничего (или `imm`) | ссылку только для чтения | по умолчанию, почти всегда |
| `mut` | изменяемую ссылку | функция меняет аргумент на месте |
| `var` | владение значением | функция забирает значение себе |
| `ref` | ссылку, происхождение которой можно назвать | функция возвращает ссылку наружу |
| `out` | место под результат | конструкторы и фабрики |

## По умолчанию — только чтение

```mojo
def describe(value: Int):
    print(value)
```

Копии не происходит: функция получает ссылку. Но менять по ней нельзя.

<CompilerError msg="error: expression must be mutable for in-place operator destination">
  <Fragment slot="meaning">
    Вы попытались изменить аргумент, переданный по умолчанию —
    а он доступен только для чтения.
  </Fragment>
  <Fragment slot="fix">
    Решите, что вам нужно:

    - менять значение у вызывающего кода — пометьте аргумент `mut`;
    - менять локально, не трогая оригинал — возьмите владение (`var`)
      или сделайте копию внутри функции.
  </Fragment>
</CompilerError>

<Aside type="note" title="`read` устарел, теперь `imm`">
  Конвенцию по умолчанию можно назвать явно. Раньше для этого писали
  `read`, сейчас компилятор просит иначе:

  ```text
  warning: 'read' is deprecated; use 'imm'
  ```

  Писать `imm` каждый раз не нужно — это и так поведение по умолчанию.
  Слово пригодится в редких случаях, когда хочется подчеркнуть намерение.
</Aside>

## `mut` — изменение на месте

```mojo
def add_page(mut pages: Int):
    pages += 1


def main():
    var pages = 10
    add_page(pages)
    add_page(pages)
    print(pages)
```

<Result>
12
</Result>

При вызове ничего дописывать не нужно — `add_page(pages)`, как в Python.
Но из сигнатуры сразу видно, что функция меняет то, что ей дали.

<PyMojo>
  <Fragment slot="python">
```python
def add_page(report):
    report["pages"] += 1   # меняет? не меняет?
```
  </Fragment>
  <Fragment slot="mojo">
```mojo
def add_page(mut report: Report):
    report.pages += 1      # видно из сигнатуры
```
  </Fragment>
  <Fragment slot="note">
    В Python ответ зависит от типа: список и словарь функция изменит,
    число или строку — нет. В Mojo про это не гадают: `mut` в сигнатуре
    или его отсутствие отвечают на вопрос сразу.
  </Fragment>
</PyMojo>

Напомним ограничение из главы [Функции](/basics/functions/): у изменяемого
аргумента не может быть значения по умолчанию (`error: 'mut' arguments
must not have defaults`). Логика простая — менять нечего, если значение
не передали.

## `var` — передача владения

Функция забирает значение себе. Вызывающий код обязан это подтвердить
сигилом `^`:

```mojo
def archive(var title: String):
    title += " (в архиве)"
    print(title)


def main():
    var title = String("Отчёт")
    archive(title^)
```

<Result>
Отчёт (в архиве)
</Result>

После вызова переменная `title` недоступна: владение ушло. Значение
уничтожится внутри `archive`, когда перестанет быть нужным там.

<Aside type="tip" title="Когда это правильный выбор">
  `var` берут, когда функция — конечная точка маршрута значения: пишет
  его в файл, кладёт в контейнер, отправляет по сети. Тогда копия была бы
  лишней работой, а ссылки недостаточно: значение должно пережить возврат
  из функции.
</Aside>

## `ref` — чтобы вернуть ссылку

Самая непривычная конвенция. `ref` нужен не для того, чтобы что-то менять,
а для того, чтобы функция могла **вернуть ссылку** на один из своих
аргументов:

```mojo
def longer(ref a: String, ref b: String) -> ref [a, b] String:
    return a if a.byte_length() > b.byte_length() else b


def main():
    var short = String("раз")
    var long = String("двадцать")
    print(longer(short, long))
```

<Result>
двадцать
</Result>

В квадратных скобках после `ref` перечислено, откуда ссылка может
происходить: из `a` или из `b`. Компилятору это нужно, чтобы гарантировать,
что возвращённая ссылка не переживёт то, на что указывает.

Результат — настоящая ссылка, в неё можно писать:

```mojo
def longer(ref a: String, ref b: String) -> ref [a, b] String:
    return a if a.byte_length() > b.byte_length() else b


def main():
    var short = String("раз")
    var long = String("двадцать")
    longer(short, long) = String("заменено")
    print(short, "|", long)
```

<Result>
раз | заменено
</Result>

<Aside type="caution" title="Внутри функции `ref` доступен только для чтения">
  Легко решить, что `ref` — это «то же самое, что `mut`». Нет: попытка
  изменить `ref`-аргумент **в теле функции** отвергается так же, как
  у обычного аргумента. Текст ошибки зависит от того, что именно вы
  пытались сделать, — для `+=` он такой:

  ```text
  error: expression must be mutable for in-place operator destination
  ```

  Изменяемость приходит от вызывающего кода: в примере выше запись
  сработала потому, что `long` — изменяемая переменная у вызывающего.
  Передайте туда неизменяемую — и запись через ссылку тоже не пройдёт.
  Нужно менять аргумент внутри функции — берите `mut`.
</Aside>

Кстати, `mut`-аргумент тоже годится как источник для возвращаемой ссылки —
но не для всех типов:

<CompilerError msg="error: cannot return 'a's origin, because it has RegisterPassable type 'Int'">
  <Fragment slot="meaning">
    Маленькие типы вроде `Int` передаются в регистрах процессора,
    то есть `mut a: Int` — это копия. Вернуть на неё ссылку означало бы
    отдать наружу ссылку на копию, которой скоро не станет.
  </Fragment>
  <Fragment slot="fix">
    Возьмите `ref` вместо `mut`: `def pick(ref a: Int) -> ref [a] Int`
    компилируется, и писать через результат тоже можно. Ограничение
    касается именно `mut`, а не чисел вообще.

    С обычным аргументом не выйдет ни так, ни так — у него просто нет
    происхождения в памяти:

    ```text
    error: value of type 'Int' doesn't have a memory origin in origin specifier
    ```
  </Fragment>
</CompilerError>

## `out` — результат через аргумент

Вы уже видели `out` в конструкторах: `def __init__(out self, ...)`.
Работает он и в обычных функциях — как именованное место под результат:

```mojo
def make_default(out title: String):
    title = String("Без названия")


def main():
    var title = make_default()
    print(title)
```

<Result>
Без названия
</Result>

Вызов выглядит как обычный: `var title = make_default()`. Разница в том,
что значение строится сразу в переменной вызывающего, без промежуточного
результата.

Рядом с `out` можно объявлять обычные аргументы, в том числе со значениями
по умолчанию. А вот два ограничения компилятор проверяет строго:

<CompilerError msg="error: function may not have multiple 'out' arguments">
  <Fragment slot="meaning">
    Больше одного `out` в функции быть не может: результат у функции один.
  </Fragment>
  <Fragment slot="fix">
    Нужно вернуть несколько значений — возвращайте кортеж, как обычно.
  </Fragment>
</CompilerError>

<CompilerError msg="error: functions must not declare both an 'out' argument and a return type">
  <Fragment slot="meaning">
    `out`-аргумент и стрелка `->` — два способа сказать одно и то же.
    Вместе они не имеют смысла.
  </Fragment>
  <Fragment slot="fix">
    Оставьте что-то одно. В обычном коде проще стрелка; `out` нужен там,
    где результат обязан строиться прямо на месте — прежде всего
    в конструкторах.
  </Fragment>
</CompilerError>

## Как выбирать

Порядок принятия решения на каждый день:

1. Функция только читает аргумент? Не пишите ничего — это уже правильно
   и не стоит ни копейки.
2. Функция меняет аргумент, и изменение должно быть видно снаружи?
   `mut`.
3. Функция забирает значение навсегда — кладёт в контейнер, пишет,
   отправляет? `var`, а на стороне вызова `^`.
4. Функция возвращает ссылку на свой аргумент? `ref` и происхождение
   в скобках.
5. Вне конструкторов `out` нужен редко — разве что в фабриках вроде
   `make_default` из примера выше.

<Aside type="note" title="Ссылка на элемент коллекции — отдельная история">
  Вернуть ссылку на элемент списка сложнее: у элемента своё происхождение,
  не совпадающее с происхождением самого списка. Компилятор скажет так:

  ```text
  error: cannot return reference with incompatible origin: 'origin_of(numbers["element"])' vs 'origin_of(numbers)'
  ```

  Разбираться с этим будем в главе
  [Времена жизни и origins](/ownership/lifetimes/) — там же, где
  и с самим понятием происхождения.
</Aside>

<Quiz>
  <QuizItem q="Чем `ref` отличается от `mut`?">
    `mut` даёт изменяемую ссылку: аргумент можно менять прямо в теле
    функции. `ref` нужен для другого — чтобы функция могла вернуть ссылку
    на свой аргумент наружу; внутри функции такой аргумент доступен только
    для чтения.
  </QuizItem>
  <QuizItem q="Что нужно написать на стороне вызова для аргумента `var`?">
    Сигил `^`: `archive(title^)`. Так в коде видно, что значение уходит
    навсегда. После этого переменная недоступна.
  </QuizItem>
  <QuizItem q="Что означают квадратные скобки в `-> ref [a, b] String`?">
    Происхождение ссылки: она может указывать на `a` или на `b`.
    Компилятору это нужно, чтобы гарантировать, что ссылка не переживёт
    значение, на которое ссылается.
  </QuizItem>
  <QuizItem q="Какую конвенцию выбрать, если функция просто читает аргумент?">
    Никакую: поведение по умолчанию и есть ссылка только для чтения.
    Копии при этом не происходит. Явное имя у этой конвенции — `imm`,
    писать его не обязательно.
  </QuizItem>
</Quiz>
