## Оформление кода

**Отступы вместо скобок.** Блоки задаются отступом, двоеточие открывает блок,
пустые строки ни на что не влияют. Всё как вы привыкли.

**Комментарии** — через `#`.

**Докстринги** — тройные кавычки первой строкой в теле функции. Более того,
расширение Mojo для VS Code умеет работать с примерами кода **внутри**
докстрингов: подсвечивает их и проверяет.

```mojo
def add(a: Int, b: Int) -> Int:
    """Складывает два числа."""
    return a + b
```

## Функции

Значения по умолчанию, именованные аргументы, возврат значения — без отличий:

```mojo
def greet(name: String, greeting: String = "Привет") -> String:
    return greeting + ", " + name + "!"
```

```mojo
greet("Мир")                                  # позиционно
greet(name="Mojo", greeting="Здравствуй")     # по именам
```

Правило «обязательные аргументы идут перед аргументами со значением
по умолчанию» тоже сохранилось.

## Управляющие конструкции

`if` / `elif` / `else`, `for ... in`, `while`, `break`, `continue` — всё
на месте. Даже редкая питоновская конструкция `for ... else` работает:

```mojo
def main():
    for i in range(2):
        print(i)
    else:
        print("цикл завершился без break")
```

`range()` ведёт себя привычно: `range(5)`, `range(2, 10)`, `range(0, 10, 2)`.

## Списки и словари

Литералы списков и генераторы списков (list comprehensions):

```mojo
var squares: List[Int] = [i * i for i in range(5)]
```

Словари доступны сразу, без импорта:

```mojo
var ages = Dict[String, Int]()
ages["Аня"] = 30
```

<Aside type="note" title="Тип нужно указать">
  `List` и `Dict` в Mojo — обобщённые (*generic*) типы, поэтому тип элементов
  указывается явно: `List[Int]`, `Dict[String, Int]`. В Python список может
  хранить что угодно вперемешку, в Mojo — только значения одного типа.
  Это цена скорости: компилятор должен знать размер элемента в байтах.
</Aside>

## Строки

Конкатенация, повторение, привычные методы:

```mojo
def main():
    print("ab" + "cd")        # abcd
    print("-" * 5)            # -----
    print("Привет".upper())   # ПРИВЕТ
    print("  x ".strip())     # x
```

<Aside type="caution" title="А вот f-строк в Mojo 1.0 нет">
  Это первое, обо что спотыкается питонист. Подробности и чем заменять —
  в главе [Что изменилось](/python-to-mojo/different/).
</Aside>

## Кортежи и множественное присваивание

```mojo
var left, right = 1, 2

var x = point[0]
```

## Ошибки и файлы

`try` / `except` / `finally` и менеджеры контекста работают привычно:

```mojo
# внутри функции, помеченной raises
with open("data.txt", "w") as f:
    f.write("привет")
```

```mojo
try:
    risky()
except e:
    print("поймали:", e)
```

Единственное отличие — функцию, которая может бросить исключение, нужно
пометить словом `raises`. Об этом — в [следующей
главе](/python-to-mojo/different/).

## Декораторы

Синтаксис `@имя` над объявлением — тот же. Набор декораторов другой
(`@fieldwise_init`, `@staticmethod`, `@parameter`), но выглядит всё привычно.

## Модули и импорты

```mojo
from std.collections.optional import Optional
```

Форма `from ... import ...` знакома, отличается только состав стандартной
библиотеки. Часть типов — `Int`, `Float64`, `Bool`, `String`, `List`, `Dict`,
`SIMD`, `Tuple` — доступна вообще без импорта.

## Даже Python можно вызвать прямо из Mojo

Если библиотеки на Mojo ещё нет, берите питоновскую:

```mojo
from std.python import Python


def main() raises:
    var math = Python.import_module("math")
    print(math.sqrt(16))
```

<Result>
4.0
</Result>

Это не «мостик на будущее», а рабочий механизм: доступны NumPy, pandas,
matplotlib и всё остальное, что установлено в вашем окружении. Подробно —
в главе [Вызов Python из Mojo](/interop/python-from-mojo/).

<Quiz>
  <QuizItem q="Почему `List` требует указания типа, а в Python список — нет?">
    Список в Python хранит ссылки на объекты, и объекты могут быть любыми.
    В Mojo список хранит сами значения подряд в памяти, поэтому компилятору
    нужно знать, сколько байт занимает элемент. Отсюда `List[Int]`
    вместо просто `list`.
  </QuizItem>
  <QuizItem q="Что из этого списка НЕ работает в Mojo: генераторы списков, for/else, f-строки, `with open`?">
    Не работают только f-строки. Остальное — генераторы списков, `for ... else`
    и менеджеры контекста — переносится из Python без изменений.
  </QuizItem>
</Quiz>
