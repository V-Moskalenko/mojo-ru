В главе о векторизации мы уже писали фигурные скобки после списка
аргументов и не объясняли, что это. Пора объяснить.

## Почему нельзя просто взять переменную

В Python вложенная функция берёт что хочет:

```python
def make_counter():
    total = 0
    def add(x):
        nonlocal total
        total += x
    return add
```

Работает это потому, что за временем жизни `total` следит сборщик
мусора. В Mojo сборщика нет, и вопрос «а что будет с `total`, когда
внешняя функция закончится» приходится решать явно.

Поэтому вложенная функция, потянувшаяся к внешней переменной без
объяснений, не соберётся:

<CompilerError msg="error: Could not infer capture convention of the captured value k">
  <Fragment slot="meaning">
    Компилятор не угадывает. Захватить переменную можно пятью разными
    способами, у каждого своя цена и свои последствия для времени жизни,
    и выбрать за вас он не берётся.
  </Fragment>
  <Fragment slot="fix">
    Написать **список захвата** — фигурные скобки после списка
    аргументов:

    ```mojo
    def main():
        var k = 4

        def times(x: Int) {imm k} -> Int:
            return x * k

        print(times(3))
    ```

    <Result output={"12"} />
  </Fragment>
</CompilerError>

Список захвата — это и есть то, что превращает вложенную функцию
в замыкание.

## Пять способов захватить

### `imm` — читаем чужое

Ссылка только для чтения. Замыкание видит **текущее** значение, а не
то, что было при объявлении:

```mojo
def main():
    var threshold = 10

    def is_over(x: Int) {imm threshold} -> Bool:
        return x > threshold

    print(is_over(15))
    threshold = 20
    print(is_over(15))
```

<Result output={"True\nFalse"} />

Пятнадцать сначала больше порога, потом меньше — замыкание ничего
не копировало, оно смотрит на живую переменную.

### `mut` — меняем чужое

```mojo
def main():
    var total = 0

    def add(x: Int) {mut total}:
        total += x

    add(5)
    add(7)
    print(total)
```

<Result output={"12"} />

Это прямой аналог питоновского `nonlocal`, только объявленный
в сигнатуре, а не внутри тела.

### `var` — берём копию

Копия делается **в момент объявления** замыкания. Дальше внешняя
переменная живёт своей жизнью:

```mojo
def main():
    var snapshot = 1

    def frozen() {var snapshot} -> Int:
        return snapshot

    snapshot = 99
    print(frozen(), snapshot)
```

<Result output={"1 99"} />

Замыкание помнит единицу, хотя переменная давно стала девяносто девятью.
Это то, чего в Python приходится добиваться трюком с аргументом
по умолчанию (`def f(x=snapshot)`).

### `var name^` — забираем себе

Значение переезжает внутрь замыкания, и снаружи его больше нет:

```mojo
def main():
    var data = String("важное")

    def take() {var data^}:
        print(data)

    take()
```

<Result output={"важное"} />

Попытка прочитать `data` после объявления замыкания даст знакомую
по разделу о владении ошибку:

```text
error: use of uninitialized value 'data'
```

Нужно это, чтобы не копировать дорогое значение: список или строку
замыкание забирает себе, а не дублирует.

<Aside type="danger" title="Пережить создателя замыкание не может">
  Напрашивается мысль: раз значение переехало внутрь, замыкание можно
  вернуть наружу и пользоваться им дальше. В Mojo 1.0 — нельзя.
  Попытка вернуть замыкание с захватом роняет компилятор:

  ```text
  error: cannot capture s because its type is not a parameter reference.
  Please submit a bug report to https://github.com/modular/modular/issues
  ```

  Руководство подтверждает: замыкания, переживающие породившую их
  область видимости, пока не поддерживаются. Вернуть можно только
  замыкание **без захвата** — о нём ниже.
</Aside>

### `ref` — наследует чужую изменяемость

`ref` не выбирает изменяемость сам, а **берёт ту, что уже есть**
у захваченной переменной:

```mojo
def main():
    var total = 0

    def bump() {ref total}:
        total += 1

    bump()
    bump()
    print(total)
```

<Result output={"2"} />

Здесь `total` объявлена через `var`, значит изменяема, значит и замыкание
может её менять. Если бы переменная пришла неизменяемым аргументом,
то же самое замыкание могло бы её только читать.

Форма нужна там, где сама внешняя функция приняла аргумент как `ref`
и решение об изменяемости принимает уже её вызывающий. В остальных
случаях берите `imm` или `mut` явно — понятнее.

<Aside type="caution" title="Регистровый аргумент через `ref` не захватить">
  Аргумент функции простого типа — `Int`, `Float64` — передаётся
  в регистре, и ссылки на него не существует:

  ```text
  error: register passible value 'v' can not be captured by 'ref'. Do you mean 'imm'?
  ```

  Компилятор сразу называет замену. То же и для `mut`. На локальные
  переменные это не распространяется — их захватывать можно как угодно.
</Aside>

## Короткие формы

Перечислять все переменные поимённо не обязательно. Одно слово в скобках
задаёт правило для всего, что замыкание использует:

| Запись | Смысл |
| --- | --- |
| `{imm}` | всё используемое — по неизменяемой ссылке |
| `{mut}` | всё используемое — по изменяемой ссылке |
| `{var}` | всё используемое — копией |
| `{var^}` | всё используемое — перемещением |
| `{ref}` | всё используемое — с их собственной изменяемостью |
| `{}` | ничего не захватывать |

Имя без слова означает `imm`: `{threshold}` — то же самое, что
`{imm threshold}`. Конвенции можно и смешивать в одном списке:
`{imm config, mut count, var label}`.

```mojo
def main():
    var a = 1
    var b = 2

    def total() {imm} -> Int:
        return a + b

    print(total())
```

<Result output={"3"} />

<Aside type="tip" title="Пустые скобки — это заявление">
  `{}` означает «я ничего снаружи не беру». Если потом кто-то допишет
  в тело обращение к внешней переменной, компилятор это поймает.
  Для вложенной функции, которая и правда самостоятельна, скобки стоит
  ставить.
</Aside>

## Лямбды

Для условия в одну строку заводить отдельную функцию незачем:

```mojo
def apply[F: def(Int) -> Int, //](value: Int, f: F) -> Int:
    return f(value)


def main():
    print(apply(7, lambda (x: Int) -> Int: x * 3))
```

<Result output={"21"} />

Типы аргументов обязательны — питоновская краткость `lambda x: x * 3`
не пройдёт, и компилятор прямо скажет, чего хочет:

```text
error: unparenthesized lambda arguments are not supported; write them in
parentheses, with types, e.g. `lambda (x: Int, y: Int) -> Int: x + y`
```

<Aside type="caution" title="Лямбда захватывает сама, а `def` — нет">
  Неожиданная асимметрия, на которой легко споткнуться. Лямбде список
  захвата **не нужен**: она берёт внешние переменные сама, по
  **неизменяемой** ссылке.

  ```mojo
  var k = 4
  var f = lambda (x: Int) -> Int: x * k
  k = 10
  print(f(7))        # 70, а не 28
  ```

  А вложенная `def` с тем же телом не соберётся без `{imm k}`.

  Обратная сторона: **менять** захваченное лямбда без списка не может.

  ```text
  error: invalid use of mutating method on rvalue of type 'List[Int]'
  ```

  Если нужен другой захват, список у лямбды тоже пишется — после
  аргументов, перед типом результата:

  ```mojo
  lambda (x: Int) {mut counter} -> Int: ...
  ```
</Aside>

## Функции высшего порядка

Чтобы принять замыкание в свою функцию, его тип объявляют **выводимым
параметром** — тем самым `//` из главы о параметризации:

```mojo
def apply[F: def(Int) -> Int, //](value: Int, f: F) -> Int:
    return f(value)
```

Так устроены и библиотечные функции: `vectorize` объявляет свой аргумент
ровно так же.

<Aside type="note" title="Когда выводимый параметр не нужен">
  Всё сказанное относится к **захватывающим** замыканиям. Их тип
  включает происхождение захваченных переменных и выглядит так:

  ```text
  def[main[origin_of(k)], {}]
  ```

  Записать его руками нельзя — отсюда и выводимый параметр.

  А вот замыкание **без захвата** имеет обычный «тонкий» тип, и его
  можно принять простым аргументом:

  ```mojo
  def apply(f: def(Int) thin -> Int, value: Int) -> Int:
      return f(value)


  def main():
      def triple(x: Int) {} -> Int:
          return x * 3

      print(apply(triple, 7))
  ```

  <Result output={"21"} />

  Слово `thin` и означает «без захваченного состояния». Такое замыкание
  — единственное, которое можно вернуть из функции наружу.
</Aside>

Главное в этом выводе — четвёртая строка. `is_large` с `{imm threshold}`
послушно изменил поведение, когда порог поменяли. `under_snapshot`
с `{var limit}` не изменил: у него своя копия, снятая при объявлении.
Один и тот же код, разные скобки — разный смысл.

<Aside type="note" title="Как выбирать">
  - читаете и хотите видеть изменения — **`imm`**;
  - меняете внешнюю переменную — **`mut`**;
  - нужен снимок на момент создания — **`var`**;
  - замыкание переживёт создателя — **`var^`**;
  - ничего не берёте — **`{}`**.

  Начинайте с `imm`: он самый дешёвый и ничего не ломает.
</Aside>

<Quiz>
  <QuizItem q="Почему вложенная функция, использующая внешнюю переменную, не собирается без фигурных скобок?">
    Потому что способов захвата пять, у каждого своя цена и свои
    последствия для времени жизни, а сборщика мусора, который сгладил бы
    разницу, в Mojo нет. Компилятор отказывается выбирать за вас
    и говорит `Could not infer capture convention`.
  </QuizItem>
  <QuizItem q="Чем `{imm x}` отличается от `{var x}`?">
    `imm` — ссылка: замыкание видит текущее значение, включая изменения,
    сделанные после его объявления. `var` — копия, снятая в момент
    объявления: внешняя переменная может меняться сколько угодно,
    замыкание будет помнить своё.
  </QuizItem>
  <QuizItem q="Лямбда использует внешнюю переменную без списка захвата и компилируется. Вложенная `def` с тем же телом — нет. Почему?">
    Так устроен язык: лямбда захватывает неявно и по **неизменяемой**
    ссылке, `def` требует явного списка. Практическое следствие: менять
    захваченное лямбда без списка не может — на попытку получите
    `invalid use of mutating method on rvalue`. Если нужен другой
    захват, список ей тоже пишется, после аргументов.
  </QuizItem>
  <QuizItem q="Как написать свою функцию, принимающую замыкание?">
    Если замыкание захватывающее — объявить его тип выводимым параметром:
    `def apply[F: def(Int) -> Int, //](value: Int, f: F) -> Int`.
    Руками такой тип не записать: он включает происхождение захваченных
    переменных. А замыкание **без** захвата имеет обычный «тонкий» тип
    и принимается простым аргументом: `f: def(Int) thin -> Int`.
  </QuizItem>
  <QuizItem q="Хочется вернуть из функции замыкание, помнящее её локальную переменную. Получится?">
    Нет. Замыкания, переживающие породившую их область видимости,
    в Mojo 1.0 не поддерживаются: попытка вернуть захватывающее
    замыкание роняет компилятор с предложением завести баг-репорт.
    Вернуть можно только замыкание без захвата — с пустым списком `{}`
    и «тонким» типом. Захват `{var name^}` нужен не для этого, а чтобы
    не копировать дорогое значение внутри своей же области видимости.
  </QuizItem>
</Quiz>
