Курс написан под **Mojo 1.2**, вышедший 22 октября 2026 года. Эта страница —
о том, что изменилось по сравнению с 1.1, а ниже — и о переходе с 1.0
на 1.1, если вы обновляете код ещё более старый.

## Коротко о 1.2

Главное в выпуске — **сопоставление с образцом**: в Mojo появился `match`.
Остальное — шлифовка: сообщения об ошибках в ограничениях, новое
написание `async`, переименования в стандартной библиотеке.

Обещание совместимости ветки 1.x на этот раз выполнено почти дословно.
Мы прогнали на 1.2 весь код курса — больше трёхсот проверок, — и ни один
пример не перестал собираться. Изменились вывод двух программ, текст
одной ошибки и поведение ещё двух мест, которые проверка без видеокарты
не замечает. Все они разобраны ниже: именно такие «тихие» изменения
опаснее всего, потому что код продолжает собираться.

| Что | Было в 1.1 | Стало в 1.2 |
| --- | --- | --- |
| `match` / `case` | не было | **есть**, плюс `if case`, `while case` и `comptime match` |
| распаковка списка | не было | `var [first, *rest] = xs` |
| текст в `where` | `where (условие, "текст")` | предпочтительно `where условие else "текст"` |
| отказ от трейта | `Movable where False` | `not Movable` |
| `async` / `await` | компилировались молча | **предупреждение**; без него — `__async` / `__await` |
| t-строка | хранила копии значений | **хранит ссылки**: значение берётся при печати |
| `log` для `Float64` | расходился с Python в десятом знаке | совпадает |
| `()` как тип | допускался | **ошибка**: пустой кортеж как тип — `Tuple[]` |
| `String.isspace()` | работал | предупреждение, замена — `is_ascii_whitespace()` |
| `std.hashlib` | модуль хеширования | **переименован** в `std.hash` |
| `has_nvidia_gpu_accelerator()` и соседи | работали | **удалены**, замена — методы `CompilationTarget` |
| `from_bytes[big_endian=True]` | работал | **ошибка**, замена — `from_bytes[endian=.big]` |
| файлы `.mojoc`, собранные 1.1 | — | **не загружаются**, пересоберите |

## Сопоставление с образцом

То, чего питонисты ждали дольше всего. `match` сравнивает значение
с образцами сверху вниз и выполняет первую подошедшую ветку:

```mojo
def status(code: Int) -> String:
    match code:
        case 200:
            return "всё хорошо"
        case 301 | 302:
            return "страница переехала"
        case c if c >= 500:
            return String("сломался сервер, код ", c)
        case _:
            return "что-то другое"
```

Образцы заглядывают внутрь структур, `Optional`, кортежей и списков,
а `comptime match` выбирает ветку при сборке и умеет сравнивать даже типы.
Синтаксис почти питоновский, но отличия есть, и одно из них коварное:
голое имя в `case` в Python перезаписывает внешнюю переменную, а в Mojo
создаёт новую, видимую только внутри ветки.

Всё это разобрано в главах по мере того, как появляются нужные типы:

- [Управляющие конструкции](/basics/control-flow/#сопоставление-с-образцом-match) —
  литералы, `|`, охранные условия, кортежи, полнота `match`;
- [Структуры](/basics/structs/#разбор-по-полям-match) — образцы
  по полям;
- [Коллекции и итераторы](/basics/collections/#optional-и-образцы) —
  `Optional`, `if case`, `while case`, образцы и распаковка списков;
- [Введение в метапрограммирование](/meta/intro/#comptime-match-выбор-из-нескольких-вариантов) —
  `comptime match`.

## Ограничения говорят по-человечески

Раньше у `where` был только машинный текст ошибки, а своё сообщение
давал `comptime assert` — ценой ошибки из глубины реализации. Теперь
текст приписывается прямо к условию, и пользователь увидит его рядом
со своим вызовом:

```mojo
def pow2[n: Int]() -> Int where n >= 0 else "показатель степени не может быть отрицательным":
    return 1 << n
```

Клауз `where` может быть несколько, у каждой своё `else`. Старая запись
`where (условие, "текст")` работает, но со временем станет устаревшей.
Подробности и итоговый пример с кольцевым буфером — в главе
[Ограничения](/meta/constraints/#ради-чего-всё-это-сообщение-для-человека).

Тем же словом `else` объясняется и отказ от трейта, который теперь
пишется через `not`: `struct Port(not Movable else "..."):` — см. главу
[Копирование и перемещение](/ownership/copy-move/#тип-который-нельзя-даже-переместить).

## `async` теперь пишется с подчёркиваниями

Асинхронность в Mojo по-прежнему нестабильна, и 1.2 говорит об этом
прямо. Старые `async` и `await` компилируются, но с предупреждением:

```text
warning: async/await support in Mojo is experimental and unstable, there are
many known issues. Please do not use it in production and do not expect
correctness. To suppress this warning, use '__async' and '__await' keywords.
That does not make the feature stable, it merely suppresses the warning.
```

`__async def` и `__await` предупреждение убирают, но, как сказано в нём
самом, стабильнее функцию не делают. Что из этого следует на практике —
в главе [Потоки, процессы и async](/performance/concurrency/#async-пока-в-разработке).

## Изменения, которые не ломают сборку

Самая важная часть страницы. Всё ниже компилируется и в 1.1, и в 1.2 —
но работает по-разному.

**t-строки хранят ссылки.** До 1.2 шаблон запоминал значения в момент
создания, теперь — ссылки на переменные:

```mojo
var n = 1
var template = t"n = {n}"
n = 2
print(template)  # 1.1: n = 1, 1.2: n = 2
```

В Python t-строки из версии 3.14 вычисляют значения сразу, так что здесь
Mojo от него отличается. Заодно изменилось имя типа в сообщениях: вместо
`TString[Int]` — `TString[origin_of(n), ...]`. Подробнее — в главе
[Строки и Unicode](/basics/strings/#форматирование-t-строки-и-format).

**Часть математики стала точнее.** `log` для `Float64` в 1.1 расходился
с Python уже в десятом знаке, а в 1.2 совпадает до последней цифры.
`exp` и дробная степень по-прежнему приближённые. Вывод из этого не «теперь
можно сравнивать через `==`», а наоборот: точность отдельных функций
меняется от версии к версии, и тест с допуском переживёт любую. См.
[Стандартная библиотека на каждый день](/basics/stdlib/#математика).

**Оптимизатор считает больше при компиляции.** Пример из главы
о тестировании умножал число из списка `[0.1, 0.2]` и показывал, как
FMA меняет последние знаки. В 1.2 компилятор научился вычислять при сборке
и такой список, и пример стал печатать `0.0`. Сама FMA никуда не делась —
на данных, которые приходят при запуске, ответ тот же, что и раньше. Мораль
для тестов в главе [Тестирование и отладка](/interop/testing/).

**Видеокарта считает немного иначе.** Фрактал из проекта о GPU на
RTX 4070 Ti SUPER под 1.1 совпадал с процессором до пикселя, а под 1.2
расходится в 337 пикселях из 307 200. Причина — слияние операций в FMA
на этапе перевода в машинный код видеокарты: флаг `--fp-mode contract=off`
возвращает полное совпадение. Обе версии правы, но тест, который ждал
совпадения бит в бит, сломался бы. Разбор — в проекте
[Первое знакомство с GPU](/projects/gpu-intro/#шаг-6-совпадает-ли-gpu-с-процессором).

<Aside type="tip" title="Как обновить свой код с 1.1">
  1. Соберите проект и посмотрите не только ошибки, но и **предупреждения**:
     `async`, `isspace` и прочее устаревшее 1.2 отмечает именно ими.
  2. `async` / `await` → `__async` / `__await`, если без асинхронности
     совсем никак. А лучше — без неё.
  3. `std.hashlib` → `std.hash`; `hash(ptr, length)` → `hash_bytes(span)`.
  4. `has_nvidia_gpu_accelerator()` → `default_accelerator().is_nvidia_gpu()`.
  5. Найдите t-строки, которые создаются заранее, а печатаются позже:
     теперь они покажут новые значения.
  6. Пересоберите все свои `.mojoc` компилятором 1.2.
  7. Прогоните тесты с дробными числами — особенно те, что сравнивают
     через `==`.
</Aside>

## Предкомпилированные пакеты снова надо пересобрать

Как и при переходе на 1.1, файл `.mojoc`, собранный предыдущей версией,
новая не загрузит:

```text
error: Mojo precompiled file is incompatible with the current version of the Mojo compiler. Precompiled file 'shapes.mojoc' version 1.1.0 is older than compiler version 1.2.0. To proceed, recreate the precompiled file with `mojo precompile`, or use the version of the compiler it was created with.
```

Теперь это уже не предположение, а закономерность: формат `.mojoc` меняется
с каждым выпуском. Как с этим жить, если вы распространяете библиотеку, —
в главе [Упаковка и распространение](/interop/packaging/).

## Что не изменилось

Проверено на компиляторе 1.2 — всё это осталось как было:

- `comptime`, `comptime if`, `comptime for`, `comptime assert` и вся
  параметризация;
- списки захвата в замыканиях; `@parameter` перед вложенной функцией
  по-прежнему помечен устаревшим;
- `parallelize` по-прежнему живёт в пакете `max`, а не в стандартной
  библиотеке;
- компилятор по-прежнему не ловит гонки данных между потоками;
- `input()` через конвейер по-прежнему получает данные только в первом
  вызове;
- `len` у строки, `readline` у файла, метод `rjust` — их как не было,
  так и нет;
- рантайм для переносимых программ — те же три библиотеки, те же
  требования к `glibc`;
- взаимодействие с Python: `Python.import_module`, преобразования `py=`,
  `PythonModuleBuilder`.

## Переход с 1.0 на 1.1

Если ваш код написан под 1.0, сначала пройдите этот шаг. Переход с 1.0
на 1.1 сломал **четыре** примера курса из ста пятидесяти — и сломал
по-настоящему, ошибкой сборки, а не предупреждением.

| Что | Было в 1.0 | Стало в 1.1 |
| --- | --- | --- |
| `InlineArray` | переходное имя для `Array` | **удалено**, только `Array` |
| `@parameter if` / `@parameter for` | предупреждение об устаревании | **ошибка** |
| присваивание без `var` (`x = 1`, `if (x := …)`) | предупреждение об устаревании | **ошибка** |
| `alias` | предупреждение, замена — `comptime` | **ошибка**, слово неизвестно |
| конвенция `read` | предупреждение, замена — `imm` | **ошибка**: `'read' was removed` |
| `@parameter` перед вложенной функцией | работал молча | предупреждение, замена — список захвата |
| `run[f]()` из `std.benchmark` | единственная форма для замыканий | **удалена**, осталась `run(f)` |
| `as_c_string_slice()` у `String` | работал молча | предупреждение, замена — `as_c_string_span()` |
| `mojo package -o файл.mojopkg` | предупреждение об устаревании | **ошибка**: нужно расширение `.mojoc` |
| файлы `.mojoc`, собранные 1.0 | — | **не загружаются**, пересоберите |
| файлы `.mojopkg` при импорте | находились | **не ищутся**: `unable to locate module` |

### `InlineArray` удалён

Самое заметное. В 1.0 `InlineArray` был вторым именем для `Array` —
оставленным ради кода, написанного до 1.0. В 1.1 его убрали:

```text
error: use of unknown declaration 'InlineArray'
```

Замена дословная: везде, где стоял `InlineArray`, пишите `Array`.
Ни поведение, ни параметры не изменились.

```mojo
var buffer = Array[Int, 8](fill=0)
```

### `@parameter` перед `if` и `for` — ошибка

В 1.0 эти формы ещё работали, ругаясь предупреждением. С 1.1 компилятор
отказывается их разбирать:

```text
error: 'for' statement does not support decorators; remove the decorator
```

Замена та же, что и была: `comptime if` и `comptime for`.

Сам декоратор перед **вложенной функцией** пока работает, но помечен
устаревшим:

```text
warning: '@parameter' is deprecated; use '@__parameter'
```

Двойное подчёркивание в предложенном имени — намёк достаточно прозрачный.
Вместо декоратора вложенной функции сегодня пишут
[список захвата](/performance/closures/).

### `run[f]()` заменена на `run(f)`

В 1.0 у функции замера было две формы, и обе неудобны: `run(f)`
не принимала захватывающие замыкания, а `run[f]()` принимала, но ругалась
предупреждением «используйте `run(f)`». Выбирать приходилось между
предупреждением и невозможностью померить.

В 1.1 параметрическую форму убрали, а обычная научилась принимать
замыкания:

```mojo
def work() {imm data}:
    ...


var report = run(work, max_runtime_secs=0.3)
```

### Пакеты: `mojo package` и `.mojopkg`

Старая команда `mojo package` работает с предупреждением, но только если
выходной файл называется `.mojoc` — расширение `.mojopkg` с 1.1 ошибка:

```text
warning: 'package' is deprecated; use 'precompile' instead
error: output path must have a '.mojoc' extension
```

Новая команда — `mojo precompile пакет -o пакет.mojoc`.

<Aside type="tip" title="Как обновить свой код с 1.0">
  1. Соберите проект и выпишите ошибки — их будет немного.
  2. `InlineArray` → `Array` заменой по всему проекту.
  3. `@parameter if` / `@parameter for` → `comptime if` / `comptime for`.
     Туда же — `var` перед каждым первым присваиванием.
  4. `@parameter` перед вложенной функцией — убрать, дописав
     [список захвата](/performance/closures/).
  5. `run[f](...)` → `run(f, ...)`.
  6. Дальше — шаги перехода на 1.2 из раздела выше.
</Aside>

## Что осталось из 1.0

Большая часть ловушек, описанных в курсе, никуда не делась. Напомним
главные — они появились ещё в 1.0 и в силе до сих пор:

| Убрано | Чем заменять |
| --- | --- |
| `fn` | `def` |
| `let` | `var` |
| `alias` | `comptime` |
| `inout` / `owned` | `mut` / `var` |
| `Stringable`, `Representable` | `Writable` |
| отрицательные индексы `x[-1]` | `x[len(x) - 1]` |

Полный список — в главе
[Что устарело](/python-to-mojo/outdated/).

<Aside type="caution" title="Почему примеров из интернета это касается особенно">
  Подавляющее большинство статей, ответов на форумах и видео о Mojo
  написаны до 1.0. В них почти наверняка встретятся `fn`, `let`, `alias`
  и `@parameter for` — то есть код, который сегодня просто не соберётся.
  А `match` в них, наоборот, не встретится вовсе: до 1.2 его не было,
  и старые советы «замените `match` цепочкой `if`» устарели.

  Это не значит, что материал бесполезен: идеи и приёмы остались. Но
  синтаксис придётся переводить, и таблицы выше — как раз словарь для
  такого перевода.
</Aside>

<Quiz>
  <QuizItem q="В старой статье написано, что `match` в Mojo нет и его надо заменять цепочкой `if`. Это так?">
    Уже нет: `match` / `case` появился в Mojo 1.2 вместе с `if case`,
    `while case` и `comptime match`. Цепочка `if` по-прежнему нужна
    для разбора `Variant` по типу — его образцами разобрать пока нельзя.
  </QuizItem>
  <QuizItem q="Код создаёт `var line = t«{count}»` в начале функции, а печатает в конце. После перехода на 1.2 вывод изменился. Почему?">
    В 1.2 t-строка хранит ссылку на `count`, а не его значение в момент
    создания, поэтому печатается последнее значение. Нужен снимок —
    превратите шаблон в строку сразу: `String(t"...")`.
  </QuizItem>
  <QuizItem q="После обновления на 1.2 каждое `async def` даёт предупреждение. Что делать?">
    Если без асинхронности можно обойтись — обойтись: компилятор прямо
    пишет, что поддержка экспериментальная и на корректность рассчитывать
    нельзя. Если нельзя — `__async` и `__await` уберут предупреждение,
    но не нестабильность.
  </QuizItem>
  <QuizItem q="Код из статьи 2024 года использует `InlineArray`. Он соберётся?">
    Нет. В 1.0 это имя ещё работало как второе имя для `Array`,
    а в 1.1 его удалили: `use of unknown declaration 'InlineArray'`.
    Замена дословная — пишите `Array`, поведение то же.
  </QuizItem>
  <QuizItem q="Проект собирается, но компилятор печатает предупреждения. Можно ли их не трогать?">
    Можно, но недолго. Предупреждение об устаревании — это анонс: так
    было с `@parameter for`, который в 1.0 предупреждал, а в 1.1 стал
    ошибкой. Разбирать их дешевле сразу, пока правка механическая.
  </QuizItem>
</Quiz>
